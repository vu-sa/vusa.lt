# Changelog

## Release entries: main changes, every role, then other fixes
Each `## vX.Y — Title (YYYY-MM-DD) {#vX-Y}` entry stays h2 (config.ts builds changelog-meta.json from it) and contains, in order:
- no meta intro about the document itself; a major opens with the `[Atsisiųsti PDF](/vusa-lt-vN-atnaujinimai.pdf)` line and the one-sentence link legend (*Gide* vs *Mano VU SA* ↗);
- the main features as numbered `### 1. …` headings, most important first (shape below);
- ALWAYS these four role `###` headings in order: Studentų atstovams, Studentų atstovų koordinatoriams, Komunikacijos koordinatoriams, Išteklių administratoriams. Inside a role, a change with a screenshot gets a `####` heading with the same shape as a main feature (no emoji, no bullet); changes without one follow as ⭐/✨/🔧 bullets below them. A role with nothing new says „Šioje versijoje naujų pakeitimų nėra.“ or links the main feature that covers it;
- `### Kiti pakeitimai ir pataisymai {#vX-Y-kiti}`: ⭐/✨/🔧 bullets.
Before listing a change under a role, check that role can actually do it (guide's Kas ką gali, Role*Seeder.php). EN mirrors the same headings and anchors without screenshots.

## Feature section shape: lead, screenshot, details, links
- First paragraph: one or two sentences naming what is new for the reader („Rezervacija nuo šiol pildoma kaip krepšelis“). No overview screenshots at the top of the entry — each frame goes right after the paragraph it shows.
- One idea per paragraph; details and the one notable exception come after the screenshot.
- Edge cases, internal rules and how-it-is-computed (trash behaviour, re-validation, completion rules shared by filters) stay in the guide, not the changelog.
- Close with one links line: `Gide: [Pranešimai](/pagrindai/pranesimai), [varpelis](/mano/pranesimai#kaip-tai-veikia) · Mano VU SA: [Pranešimų nustatymai](app:/mano/profile/notifications)`. Bullets end the same way. EN uses `Guide:` / `My VU SR:`. Don't use a markdown list for links — it merges with the ⭐/✨/🔧 bullets that follow.
- Link text names the page or UI label, never „Plačiau“. `app:/mano/…` opens the platform in a new tab with ↗ (web and PDF); a plain `/mano/…` link is the guide's Mano section. Take app paths from `route:list`; no `{id}` routes.
- Bullet titles name the change in the reader's words, quoting UI labels in „…“ („Darbotvarkės klausimai „Nerodoma““), not implementation terms.

## Changelog screenshots: reuse guide frames, annotate with highlights
Reuse an existing guide frame when it already shows the change. When the reader needs to know where to look, capture an annotated variant `vN-<topic>` right after the clean frame in the same browser test: `docsScreenshot($page, 'vN-topic', highlights: ['[data-slot=…]', …])` draws numbered red boxes. Explain the numbers only in that image's `caption`, in numeric order („(1) …, (2) …“); the body text never cites them. Overview frames (e.g. the home page) stay unannotated. Highlights don't scroll and throw when a selector is off screen, so position the page first. A genuinely new frame is captured clean and also embedded in its guide page; annotated `vN-*` frames stay changelog-only. `node docs/pdf/build-release.ts` builds the PDF from the newest vN.md.

## Freeze a major's release notes when the next one starts
Screenshots are regenerated by CI on every deploy, so old notes would silently show the newer UI. When vN+1.md is created: commit vN's frames to `docs/public/releases/vN/` and its built PDF, point vN.md's images and PDF link at those files, and drop the `vN-*` docsScreenshot calls from the browser tests.

## Changelog tone: plain and measured
Write like a short release note from a colleague, not an advert: neutral statements of what changed. Describe, don't instruct — the guide gives steps, so prefer „galima“, „rodoma“, „nuo šiol“ over imperatives („pasirink“, „pradėk“); keep tu only where it reads naturally („tavo krepšelis“). No pep or colloquial filler („po ranka“, „Nebereikia laukti“, „nepradingsta“); one light aside in a whole release is fine („kaip el. parduotuvėje 😅“). Give a concrete example where a category is abstract („pvz., narių registracijos“). Don't overclaim: if only some actions moved, say „dalis“, not „visa“. Headings name the change („Atsakymas į koordinatoriaus užklausą“). Each fact appears once — don't repeat a caption in the text. Don't describe fixes to the unreleased candidate itself („vėl sutampa“) — the reader never saw the broken state.
